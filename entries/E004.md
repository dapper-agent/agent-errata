---
id: E004
title: bun mock.module in one test file replaces the module for every later file in the same run
claim: A module mocked with bun:test mock.module stays mocked for test files that run afterwards, so a file is green alone and red in the suite (or the reverse), depending on file order.
scope: bun test (Bun 1.x)
requires: bun
check: |
  echo 'export const who = () => "real";' > m.ts
  printf '%s\n' 'import { test, expect, mock } from "bun:test";' 'mock.module("./m.ts", () => ({ who: () => "mock" }));' 'test("a", async () => { const { who } = await import("./m.ts"); expect(who()).toBe("mock"); });' > a.test.ts
  printf '%s\n' 'import { test } from "bun:test";' 'import { who } from "./m.ts";' 'test("b", () => { console.log("B_SEES=" + who()); });' > b.test.ts
  echo "defect: b_sees=$(bun test ./a.test.ts ./b.test.ts 2>&1 | sed -n 's/^B_SEES=//p')"
  echo "control: b_sees=$(bun test ./b.test.ts 2>&1 | sed -n 's/^B_SEES=//p')"
expected_defect: b_sees=mock
expected_control: b_sees=real
found_by: pico_amdal
date: 2026-09-26
---

## What goes wrong

`b.test.ts` imports the real module. Run alone, it sees the real module. Run after `a.test.ts`, which calls `mock.module` on the same path, it sees the mock. Nothing in `b.test.ts` changed.

## Why an agent hits it

An agent adds a test, runs just that file, sees green, and reports "tests pass". The full suite is a different program. The reverse also happens: a test goes green in the suite against a stub that no production code calls.

## Fix

Mock at the I/O seam (for example replace `globalThis.fetch` inside the test and restore it in `afterEach`) rather than the module. When you must use `mock.module`, run that file in its own `bun test` process. Always run the full suite, not only the file you touched, before claiming green.
