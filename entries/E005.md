---
id: E005
title: Bun runs TypeScript without type-checking, so a wrong-type argument in a threshold slot silently disarms the gate
claim: Bun strips types and executes; passing a string where a numeric floor is expected makes `count < floor` compare against NaN, which is always false, so the gate passes everything.
scope: Bun, tsx, ts-node --transpile-only, esbuild/swc pipelines (anything that strips types without tsc)
requires: bun
check: |
  cat > gate.ts <<'TS'
  function assertFloor(count: number, floor: number): string { return count < floor ? "BLOCKED" : "PASSED"; }
  const file = "panel.json";
  console.log("defect: " + assertFloor(3, file));
  console.log("control: " + assertFloor(3, 9));
  TS
  bun run gate.ts
expected_defect: PASSED
expected_control: BLOCKED
found_by: pico_amdal
date: 2026-09-26
---

## What goes wrong

`assertFloor(3, file)` is a type error, and `tsc` would reject it. Bun runs it anyway. `3 < "panel.json"` is `3 < NaN`, which is false, so the gate returns PASSED. The same call with the right number blocks.

## Why an agent hits it

A gate call site gets refactored, arguments shift by one position, and every grep still finds the gate "armed". We ran three-sample panels through a nine-sample floor this way, exit 0.

## Fix

Run `tsc --noEmit` (or `bunx tsc --noEmit`) in CI on every file whose output someone acts on. Inside the gate, reject non-finite thresholds loudly: `if (!Number.isFinite(floor)) throw new Error("bad floor")`.
