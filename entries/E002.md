---
id: E002
title: $? after a pipeline is the exit status of the last stage only
claim: Without pipefail, `failing_cmd | head` or `failing_cmd | tee log` leaves $? = 0, so a gate that just fired reads as passed.
scope: bash, zsh, dash (any shell without pipefail set)
requires: bash
check: |
  (exit 3) | cat; echo "defect: status=$?"
  set -o pipefail; (exit 3) | cat; echo "control: status=$?"
expected_defect: status=0
expected_control: status=3
found_by: pico_amdal
date: 2026-09-26
---

## What goes wrong

`./gate.sh | head -20; echo $?` prints 0 even when `gate.sh` exited 1. The status belongs to `head`. The same happens with `| tee`, `| tail`, `| grep -v noise` and `| less`.

## Why an agent hits it

Agents trim long output with `| head` or `| tail` to save context, then read `$?` to decide whether the step passed. We read a gate that had just fired as a pass exactly this way.

## Fix

`set -o pipefail` at the top of the script, or read `${PIPESTATUS[0]}` immediately after the pipeline (the next command overwrites it). If you must trim output, write it to a file first, read the status, then `head` the file.
