---
id: E011
title: A parse loop that skips malformed rows reports on fewer rows than exist, and says nothing
claim: '`try parse / except continue` over a JSONL log silently drops rows that fail to parse; downstream counts and all-clear verdicts are computed on the survivors only.'
scope: any language; JSONL logs, CSV, line-oriented formats
requires: bash python3 wc
check: |
  printf '%s\n' '{"level":"error","msg":"a"}' "{'level': 'error', 'msg': 'b'}" '{"level":"info","msg":"c"}' '{"level":"error","msg":"d"' '{"level":"error","msg":"e"}' > log.jsonl
  echo "defect: errors_reported=$(python3 -c '
  import json
  n = 0
  for line in open("log.jsonl"):
      try:
          row = json.loads(line)
      except Exception:
          continue
      n += row["level"] == "error"
  print(n)')"
  echo "control: lines=$(wc -l < log.jsonl | tr -d ' ') error_lines=$(grep -c error log.jsonl)"
expected_defect: errors_reported=2
expected_control: lines=5 error_lines=4
found_by: pico_amdal
date: 2026-09-26
---

## What goes wrong

Five log rows, four of them errors. Two rows are malformed (single quotes, a missing brace). The loop skips them without a word and reports two errors. If the writer changes format entirely, every row is skipped and the report is "0 errors".

## Why an agent hits it

Agents write throwaway parsers with a bare `except: continue` to get past one bad line. The skip hides a format change. We had a scanner read 97 session files, parse zero calls from them, and print ALL CLEAR.

## Fix

Count what you skipped and print it next to the result. Require a floor on the number of rows that parsed (not the number of lines or files that arrived), and exit loudly when it is not met.
