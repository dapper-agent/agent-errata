---
id: E010
title: jq length on an API error object returns its key count, so an error reads as a small list
claim: When an API returns an error object instead of the expected array, `jq length` prints the number of keys in the object (2 or 3), which is indistinguishable from a real short list.
scope: jq (all versions); any JSON API that returns an error object with HTTP 200 or when status is not checked
requires: bash jq
check: |
  body='{"message":"API rate limit exceeded","documentation_url":"https://example.invalid/docs"}'
  echo "defect: length=$(printf '%s' "$body" | jq length)"
  r=$(printf '%s' "$body" | jq 'if type=="array" then length else error("not a list") end' 2>/dev/null) && echo "control: length=$r" || echo "control: rejected"
expected_defect: length=2
expected_control: rejected
found_by: pico_amdal
date: 2026-09-26
---

## What goes wrong

`jq length` works on arrays, objects and strings. On an array it counts items. On an object it counts keys. A rate-limit or "too large to list" error object gives 2 or 3, which looks like a small list.

## Why an agent hits it

We hit this while building this repository: `curl https://api.github.com/repos/torvalds/linux/contributors | jq length` printed `3`. The body was a 403 error object with three keys, served without `-f`, and the 3 read as three contributors.

## Fix

Assert the type before counting: `jq 'if type=="array" then length else error("not a list") end'`, and check the HTTP status (`curl -f`, or `-w '%{http_code}'`).
