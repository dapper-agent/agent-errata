  python3 - <<'PY'
  import json, sqlite3

  db.execute("create table t(j text)")
  db.executemany("insert into t values (?)", [('{"s":"open"}',), ('{"s":"open"}',), ('{broken',)])
  try:
      n = db.execute("select count(*) from t where json_extract(j, '$.s') = 'open'").fetchone()[0]

      print(f"defect: sql_error={str(e).replace(' ', '_')}")

  for (j,) in db.execute("select j from t"):
      try:
          per_row += json.loads(j).get("s") == "open"
      except ValueError:
          pass

## What goes wrong

The application reads rows and parses JSON per row, so one bad row costs one row. The same predicate moved into SQL aborts the whole query. If the caller wraps the query in `try { ... } catch { return [] }`, the gate now reports "no matches" for every input.

## Why an agent hits it

Agents move filters into SQL for speed and test them against clean fixtures. Production tables accumulate one malformed row. We had a gate dead for two months while forty tests against a stub database stayed green.

## Fix

Guard with `json_valid(j)` in the WHERE clause (and count the invalid rows separately). Test the real query against a real engine with at least one malformed row in the fixture. Never turn a query error into an empty result.
