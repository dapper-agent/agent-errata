claim: If any file loaded by the test runner calls process.exit at import time, the runner stops, prints no pass/fail summary, and exits with the code passed to exit, hiding failures.
scope: bun test (Bun 1.x); worth running against other runners that execute test files in-process

check: |
  printf '%s\n' 'import { test, expect } from "bun:test";' 'test("must fail", () => { expect(1).toBe(2); });' 'process.exit(0);' > x.test.ts
  out=$(bun test 2>&1); st=$?
  echo "defect: exit=$st summary_lines=$(printf '%s\n' "$out" | grep -cE '^ *[0-9]+ fail')"
  sed -i.bak '/process.exit/d' x.test.ts
  out=$(bun test 2>&1); st=$?
  echo "control: exit=$st summary_lines=$(printf '%s\n' "$out" | grep -cE '^ *[0-9]+ fail')"
expected_defect: exit=0 summary_lines=0
expected_control: exit=1 summary_lines=1

## What goes wrong

A test file (or a script it imports) ends with `process.exit(0)`, typically because it was written as a CLI and later imported by a test. `bun test` loads it, the process exits 0, and the runner never prints its summary. A failing test in the same file is never reported.

## Why an agent hits it

Agents check the exit code. Exit 0 means "suite green". The missing summary line is the only tell, and nobody reads for an absence.

## Fix

Treat "no summary line" as a failed run, whatever the exit code: parse for `N pass` / `N fail` and require them. Guard CLI entry points with `if (import.meta.main)` so importing a script does not run it.
