---
id: E008
title: A substring containment check stays green when the member that is a prefix of the others is deleted
claim: Checking required items with `includes` / substring match passes for a missing item whenever it is a prefix of an item that is still present.
scope: any language; substring checks (`includes`, `in`, `grep` without -x, shell `case *x*`)
requires: bash grep
check: |
  required="/en/ /en/about /en/pricing"
  present="/en/about /en/pricing"
  miss=0; for r in $required; do case " $present" in *"$r"*) ;; *) miss=$((miss+1));; esac; done
  echo "defect: missing=$miss"
  miss=0; for r in $required; do printf '%s\n' $present | grep -qxF -- "$r" || miss=$((miss+1)); done
  echo "control: missing=$miss"
expected_defect: missing=0
expected_control: missing=1
found_by: pico_amdal
date: 2026-09-26
---

## What goes wrong

A parity gate asks: does the page link to `/en/`, `/en/about` and `/en/pricing`? Delete the `/en/` link and the substring check still finds `/en/` inside `/en/about`. The shortest member is the one that can never fail.

## Why an agent hits it

Agents write presence gates with `includes` because it is one line. We ran a language-parity gate that stayed green with its root URL deleted.

## Fix

Match to a boundary: exact field equality, `grep -x`, a delimiter, or a lookahead. When you write the test for the gate, delete the shortest member as the negative case, since that is the one a substring check cannot catch.
