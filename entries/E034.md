---
id: E034
title: A score that averages only the sub-probes that returned goes up when a sub-probe fails, so the failure reads as a better result
claim: 'An evaluator that scores a dimension as the mean of several sub-probes, and drops a sub-probe that failed to score, averages over the ones that returned. When the failed one would have scored low, the dimension comes out higher than the complete run would have given. Nothing errors, and the published number looks like an ordinary score. A fill value for the failed sub-probe that can sit above its true score (a fixed default, or a fraction of the others) has the same effect, only smaller.'
scope: any scorer that aggregates sub-scores and treats a missing one as skipped or filled (LLM-judge rubrics, eval harnesses, health scores). The check uses jq; pandas Series.mean() has the same behaviour by default (skipna=True)
requires: jq
check: |
  # The fifth sub-probe failed to score. When it did score, it scored 20.
  failed='[92.5,92.5,92.5,92.5,null]'
  complete='[92.5,92.5,92.5,92.5,20]'
  # Replace either aggregator with your own to test it.
  skip='[.[] | select(. != null)] | add / length'
  closed='if any(.[]; . == null) then error("unscored") else add / length end'
  arm() {
    f=$(printf '%s' "$failed" | jq -c "try ($1) catch \"unscored\"") || return 1
    c=$(printf '%s' "$complete" | jq -c "$1") || return 1
    r=$(jq -nr --argjson f "$f" --argjson c "$c" 'if ($f|type) == "number" and $f > $c then "yes" else "no" end') || return 1
    echo "failed=$f complete=$c raises=$r"
  }
  if d=$(arm "$skip") && k=$(arm "$closed"); then
    echo "defect: skip-failed $d"
    echo "control: fail-closed $k"
  else
    echo "jq-failed"
  fi
expected_defect: skip-failed failed=92.5 complete=78 raises=yes
expected_control: fail-closed failed="unscored" complete=78 raises=no

## What goes wrong

A dimension is the mean of five sub-probes. One sub-probe's judge call comes back empty, so that sub-probe has no score. The scorer skips it and averages the four that returned. If those four average 92.5 and the missing one would have scored 20, the dimension is recorded as 92.5 where the complete mean is 78. The failure made the result 14.5 points better, and the record carries no sign that anything failed.

The defect arm runs the skipping aggregator on the failed run and on the complete run and asks whether the failed run scored higher: it does. The control arm runs a fail-closed aggregator, which refuses to score a dimension with a missing sub-probe, on the same two inputs: the failed run comes out unscored, so it cannot score higher. Same inputs, same comparison, so a broken jq or a wrong path breaks both arms, not one.

## Why an agent hits it

Skipping is the default in common tools. `pandas.Series.mean()` skips NaN unless told otherwise (`skipna=True`): on `[92.5, 92.5, 92.5, 92.5, NaN]` it returns 92.5, measured on pandas 3.0.6. `numpy.nanmean` does the same by design, while plain `numpy.mean` returns NaN. In hand-written code it is `[s for s in scores if s is not None]` before the mean, written to stop one empty response from crashing the run.

Whether the skip raises a given dimension depends on where the failed sub-probe sits: it raises it whenever the skipped sub-probe would have scored below the mean of the rest. In the run this entry comes from, three answers came back mostly empty; under the rebuilt rubric they scored 20, 70 and 100, and the skip raised the dimension for two of the three.

## Fix

Pick one rule and test it: a failed sub-probe can never make the dimension score higher than the complete run would have. Two rules meet that. Mark the dimension unscored (fail closed) and say so on the record. Or fill the failed sub-probe with the lowest score the rubric allows, which can only lower the mean. Then point the check above at your own aggregator, with a failed sub-probe whose true score is low, and assert `raises=no`.

A partial fix still fails the check. Filling the failed sub-probe with the lower of 60 and the mean of the others gives (4 × 92.5 + 60) / 5 = 86 for this record: 8 points above the complete 78 instead of 14.5. The finder runs that fill today and says the check should fail it. On the same seven answers the rebuilt rubric returned 0 empty responses in 42 calls, so the fill has not fired on that corpus; 86 is what it records if the sub-probe fails again.
