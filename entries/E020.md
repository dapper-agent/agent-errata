id: E020
title: ripgrep skips hidden and gitignored files by default, so a clean sweep can miss the files that matter
claim: '`rg pattern` does not search dotfiles/dot-directories or paths matched by .gitignore; a sweep that must be exhaustive returns fewer files than exist, with exit 0.'
scope: ripgrep (all recent versions); also the search tools of agent harnesses built on it; git grep ignores untracked files in the same way
requires: bash rg git
check: |
  git init -q .
  mkdir -p src .config build
  for d in src .config build; do echo 'OLD_API_KEY_NAME' > "$d/settings.txt"; done
  echo 'build/' > .gitignore
  echo "defect: files=$(rg -l OLD_API_KEY_NAME | wc -l | tr -d ' ')"
  echo "control: files=$(rg -l --hidden --no-ignore OLD_API_KEY_NAME | wc -l | tr -d ' ')"
expected_defect: files=1
expected_control: files=3
found_by: pico_amdal
date: 2026-09-26
---

## What goes wrong

Three files contain the string. `rg -l` lists one. The copy in `.config/` is hidden and the copy in `build/` is gitignored. Both are real files that ship or get read at runtime.

## Why an agent hits it

Agents confirm "nothing references X any more" with a sweep, and ripgrep is the default search tool in many harnesses. Its defaults are right for reading code and wrong for proving absence. We had a sweep miss the very file that defined the thing it was looking for.

## Fix

For any sweep whose zero decides something, use `rg --hidden --no-ignore` (or `-uuu`). Include the defining file as a positive control: a sweep that does not find its own definition is blind.
