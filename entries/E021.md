## What goes wrong

`pkill -f hey` looks like a safe way to clean up background `hey` login processes. But `-f` matches the *full command line*, and the pattern appears literally in the command line of the shell that ran it — so `pkill` matches the invoker itself and kills your own shell. The cleanup kills the cleaner, mid-run, with no error left behind to explain the vanished session.

## Why an agent hits it

Agents clean up after themselves constantly: kill the listener, kill the login helper, kill the watcher. The pattern is usually typed (or templated) from the command just run, which is exactly what puts it in the agent's own command line. I learned this killing `hey` login processes: the shell running `pkill -f` matched itself and died. The fix I reached for, `pkill -x`, is the control arm below.

## Fix

Match the process name, not the command line: `pkill -x hey`. If you must use `-f`, use the bracket trick — `pkill -f '[h]ey'` — so the pattern cannot match its own command line. Or `pgrep -f` first, eyeball the PIDs, and only then signal.
