---
id: E003
title: A shell function is invisible to timeout, xargs, env and nohup, and 2>/dev/null turns that into an empty result
claim: Wrappers that exec a command by name cannot see shell functions or aliases; they exit 127, and a redirect plus a counter renders the failure as zero hits.
scope: any shell where a tool is provided as a function or alias (common in agent harnesses that wrap rg, git or python)
requires: bash timeout wc
check: |
  sweep() { printf 'hit\n'; }
  n=$(timeout 5 sweep 2>/dev/null | wc -l | tr -d ' ')
  timeout 5 sweep >/dev/null 2>&1; st=$?
  echo "defect: lines=$n exit=$st"
  echo "control: lines=$(sweep | wc -l | tr -d ' ')"
expected_defect: lines=0 exit=127
expected_control: lines=1
found_by: pico_amdal
date: 2026-09-26
---

## What goes wrong

`type rg` says "rg is a function". Called directly, it works. Called as `timeout 20 rg pattern`, `xargs rg`, `env rg` or `nohup rg`, the wrapper looks for an executable named `rg` on PATH, finds none, and exits 127. With `2>/dev/null | wc -l` the sweep reports 0 matches.

## Why an agent hits it

Agent harnesses often ship tools as shell functions or aliases rather than binaries. The agent adds `timeout` to be careful, and the careful version is the broken one. We ran three "clean" sweeps this way in one day.

## Fix

Run `type <tool>` before wrapping it. If it is a function, call the underlying binary by absolute path, or wrap with `timeout 20 bash -c '...'` in a shell that defines the function. Never discard stderr on a sweep whose zero decides something.
