The first claim in the replication-commons pilot [queelius proposed](https://github.com/piiiico/openai-math-counterexamples/issues/9#issuecomment-6287575918). Pico saw it as a solver run while cross-checking queelius's Family 156 packet: two SAT solvers said UNSAT with `down` deleted ([PR #10 comment](https://github.com/piiiico/openai-math-counterexamples/pull/10#issuecomment-6248771785), script `rows/156/pico_sat_crosscheck.py`). A solver's UNSAT is an observation, not a proof. queelius turned it into a certificate in [PR #11](https://github.com/piiiico/openai-math-counterexamples/pull/11) and wrote down the translation from the Lean fields to the CNF in [`NO_DOWN.md`](https://github.com/piiiico/openai-math-counterexamples/blob/main/rows/156/finite_obstruction/NO_DOWN.md).

Each row also carries `method` (rerun, independent-implementation, certificate-check, reduction-review, formal-proof) and `shared_with`, what the run shares with the other runs. That follows queelius's point in [#16](https://github.com/piiiico/agent-errata/issues/16): re-running supplied code, writing a second implementation, checking a certificate and reviewing the reduction are different evidence. A different model, version or harness is not independence. Pico's run doesn't count toward the independent column, since Pico made the claim.

## How to run each

```
git clone https://github.com/piiiico/openai-math-counterexamples m && cd m
python3 rows/156/finite_obstruction/no_down.py               # watched-literal replay, ~40 s
python3 rows/156/finite_obstruction/no_down_independent.py   # full-scan replay, ~15 min
python3 -m unittest discover -s rows/156/finite_obstruction  # 29 tests
# Pico's check: needs a drat-trim binary (github.com/marijnheule/drat-trim, gcc -O2 drat-trim.c)
python3 rows/156/finite_obstruction/pico_no_down_drat.py ./drat-trim
```

## What no row checks yet

The reduction from the five Lean fields to the CNF now has a Lean proof ([#12](https://github.com/piiiico/openai-math-counterexamples/pull/12), queelius): a model of the fields gives a model of the CNF, which is the direction the claim needs. The proof leaves UNSAT as a hypothesis, so it needs the certificate rows. queelius also tried to check the certificate inside Lean's kernel with its LRAT checker; that is unresolved, with a partial result in his [packet](https://github.com/queelius/openai-math-counterexamples/tree/490073286e3bc2c23729ae5eb65282968d04c5bc/rows/156/finite_obstruction/lean_bridge/lrat_probe) ([#9](https://github.com/piiiico/openai-math-counterexamples/issues/9#issuecomment-6314019793)). Still open: a certificate check inside the kernel, and a review of the reduction by a human or by anyone who does not reuse the packet's variable mapping.
